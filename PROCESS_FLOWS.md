```
50ms           編碼為 Base64              camera.js     前端記憶體
100ms          WebSocket 發送             前端          後端

400ms          WebSocket 返回登入訊息     後端          前端

```

## 6. 資料轉換流程

### 影像到購物車的轉換

```
原始影像 (本地相機)
    │
    ├─> OpenCV 讀取 (BGR 格式)
    │   ├─> 寬度: 640px
    │   ├─> 高度: 480px
    │   └─> 顏色空間: BGR
    │
    ├─> 編碼為 JPEG (80% 品質)
    │   └─> Base64 編碼
    │
    ├─> WebSocket 傳輸
    │   ├─> 幀編號
    │   ├─> 時間戳記
    │   └─> Base64 data
    │
    ├─> 後端接收解碼
    │   ├─> Base64 -> 二進位
    │   └─> 二進位 -> NumPy array (BGR)
    │
    ├─> YOLO 推論
    │   ├─> RGB 轉換
    │   ├─> 神經網路處理
    │   └─> 輸出: [class_id, confidence, bbox]
    │
    ├─> 後處理
    │   ├─> 信心度過濾 (>= 0.8)
    │   ├─> 查詢商品資訊
    │   └─> 轉換為商品對象
    │
    ├─> 購物車服務
    │   ├─> 檢查商品是否存在
    │   ├─> 加入或更新數量
    │   └─> 計算合計金額
    │
    └─> WebSocket 傳送更新
        └─> 前端 UI 更新
```

## 9. 效能指標

```
操作                 時間消耗        頻率
─────────────────────────────────────────
影像擷取             ~10ms          每幀
Base64 編碼          ~40ms          每幀
WebSocket 傳送       ~50ms          每幀
後端解碼             ~10ms          每幀
YOLO 推論            ~100-200ms     取決於 GPU
人臉偵測            ~150-300ms     每秒
人臉比對            ~10ms          (若有偵測到臉)
購物車更新          ~5ms           (若偵測到商品)
─────────────────────────────────────────

整個流程 (偵測到購物車更新):
- 最佳情況: ~300ms (無人臉)
- 一般情況: ~400-500ms
- 最差情況: ~600ms (包含人臉比對)

QPS (Queries Per Second):
- 影像幀發送頻率: 1 幀/秒 = 1 QPS
- 實際 YOLO 處理: 0.2秒間隔 = 5 QPS
- 人臉處理: 1秒間隔 = 1 QPS
```

## 10. 錯誤處理流程

```
前端錯誤
├─> 鏡頭存取失敗
│   └─> showError() -> 顯示錯誤訊息
├─> WebSocket 連接失敗
│   └─> handleReconnect() -> 指數退避重連
└─> 結帳失敗
    └─> alert() / showToast() -> 提示用戶

後端錯誤
├─> YOLO 模型加載失敗
│   └─> 拋出異常 -> 應用停止
├─> MongoDB 連接失敗
│   └─> 拋出異常 -> 應用停止
├─> 人臉偵測異常
│   └─> 打印日誌 -> 繼續運行
├─> WebSocket 錯誤
│   └─> 斷開連接 -> 清理資源
└─> 結帳驗證失敗
    └─> HTTPException -> 返回 400/500 錯誤

資料庫錯誤
├─> 重複電話號碼 (unique constraint)
│   └─> ValueError -> 提示註冊失敗
└─> 查詢失敗
    └─> 記錄日誌 -> 返回空結果
```
